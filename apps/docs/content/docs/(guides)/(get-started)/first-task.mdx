---
title: Your first task
description: Watch Jinion take a request from a question to tested code.
---

Type what you want done and press `enter`:

```text
add rate limiting to the api
```

Jinion looks through the code first. When a choice is yours to make, it asks instead of guessing:

```terminal
 {success|[x]} {bold|Glob:} {code|src/middleware/*.ts} {muted|4 files}
 {border||--} {muted|ts} src/middleware/index.ts
 {border||--} {muted|ts} src/middleware/cors.ts
 {border||--} {muted|ts} src/middleware/request-id.ts
 {border|'--} {muted|ts} src/middleware/error-handler.ts

 {thinking,italic|No limiter exists yet. There is a TODO in the login route and a `TooManyRequests` error}
 {thinking,italic|already defined in src/http/errors.ts, which I can reuse instead of hand-rolling a 429.}

 {thinking,italic|Middleware are plain (req, res, next) functions composed in src/server.ts, so a limiter}
 {thinking,italic|fits in as one more entry. The real decision is storage: a Map is enough for one process,}
 {thinking,italic|but behind a load balancer every instance would count separately. I will ask instead of}
 {thinking,italic|guessing.}

 {accent|[-] Waiting for your answer…} {muted|0s · esc to interrupt}

{accent|+- Ask} {muted|1/3 · storage} {accent|----------------------------------------------------------------------+}
{accent||} {bold|Where should the limiter keep its counters?}                                              {accent||}
{accent||                                                                                          |}
{accent|+------------------------------------------------------------------------------------------+}
{accent||} {code|> 1.} {code,bold|In-memory}                                                                           {accent||}
{accent||}      {muted|single process, zero dependencies}                                                   {accent||}
{accent||}   2. Redis                                                                               {accent||}
{accent||}      {muted|shared across instances, needs REDIS_URL}                                            {accent||}
{accent||}   3. In-memory behind a store seam                                                       {accent||}
{accent||}      {muted|Redis can be added later}                                                            {accent||}
{accent||}   4. Other (type your own)                                                               {accent||}
{accent|+------------------------------------------------------------------------------------------+}
{accent||} Enter {muted|select ·} n {muted|note ·} Up/Down {muted|move ·} Esc {muted|cancel}                                        {accent||}
{accent|+------------------------------------------------------------------------------------------+}
```

Then it edits the files, runs the tests, and fixes what fails. Every edit shows as a diff in the conversation. At the
end you get a short summary of what changed and how it was checked.
